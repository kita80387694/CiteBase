# 第三阶段人工质量评审协议

规则版本：`citebase-human-quality-v1`。本协议定义操作规则，不代表已发生真人评审。数据与参考要点由开发 Agent 编写，属于待真人审查的测试材料，不是人类评分。

## 数据与盲评

新数据位于 `samples/phase3-quality/`，共 12 份原创虚构 Markdown 文档、120 道题（96 可回答、24 不可回答），以 CC0-1.0 分发。不要作为现实业务规范。开发、验证、独立测试各 40 题，每组 8 道不可回答；6 个主题的两份文档与全部题目完整留在同一划分。

seed=20260930，通过生成器中明确的 LCG/Fisher-Yates 算法冻结整主题顺序：cobalt、brass 为开发；elm、dahlia 为验证；aster、flint 为独立测试。测试集可审查标签与数据完整性，但不得在配置冻结前运行结果来选参数。旧测试集不再视为未见测试集。

人工评审页应隐藏配置、模型策略和试验臂名称，用随机化匿名编号展示单份回答。评分前展示问题、原文、参考要点、该回答引用与实际终态。失败响应不能消失；应明确显示其不能提供有效答案，不允许评审者凭空补全答案。项目分配时对全部回答做一次带 seed 的随机打乱，分配后的 ordinal 固定并可审计。当前不是为每位评分者独立随机排序；题目顺序与配置名称不作为评分依据。

初始评审按 `scripts/quality-registration.mjs` 从开发集与验证集各预选 20 题，共 40 题 × 向量基础 RAG/原 Agent 两臂，至少 80 份回答。预选按 topic/category 轮转、组内题号 SHA256 排序，不查阅结果；注册文件保存精确 caseIds。现有评测 API 额外生成的混合检索行完整保留为辅助结果，不进入这 80 份主配对。第二名真人独立复核至少 16 份（20%），当前实现对全体回答做带 seed 的随机打乱，选择前 ceil(回答数×20%) 份作双评，不是分层抽样；在评分前保存分配请求和返回的任务映射，事后报告该随机样本的题型、可回答性与终态覆盖，不宣称各层均衡。第二评分者不能先看到第一人的结论。独立测试正式质量比较对 40 题 × 基础 RAG/原 Agent/修复 Agent 的 120 份回答另行真人评分，不能复用开发集评分。

## 评分维度

每个维度可取明确值，未评审为 null；不适用必须另有原因，不能与“正确”合并。

| 维度 | 取值与规则 |
| --- | --- |
| 正确性 `correctness` | `INCORRECT`（分析映射 0）：核心结论错误/与原文矛盾；`PARTIAL`（1）：部分正确但有实质错误；`CORRECT`（2）：核心要点正确，无实质错误；`NA`：不适用并注明原因 |
| 完整性 `completeness` | `INCORRECT`（0）：未覆盖必需要点；`PARTIAL`（1）：覆盖部分；`CORRECT`（2）：覆盖所有必需要点；`NA`：不适用。合理简短答案可获 CORRECT，不按长度奖励 |
| 引用支持 `citationSupport` | `UNSUPPORTED`（0）：引用不支持重要结论；`PARTIAL`（1）：部分支持但重要断言缺证据；`SUPPORTED`（2）：所有重要事实有实际引用支持；`NA`：纯拒答无事实引用等不适用情况 |
| 无依据内容 `unsupportedContent` | `NONE`：未发现；`PRESENT`：至少一处实质断言缺乏资料支持；`NA`：不适用。依据须指出具体断言 |
| 拒答 `refusal` | `CORRECT_REFUSAL`：不可回答且明确拒答；`INCORRECT_REFUSAL`：可回答却拒答；`NOT_REFUSED`：没有拒答；`NA`：无法适用。应拒未拒通过 answerable=false 且 NOT_REFUSED 推导，不存在额外 API 枚举 |

括号中的 0/1/2 仅为分析映射，API 导入必须使用上表字符串，不能提交数字或布尔值。一次已提交评分要求全部五个维度与非空 rationale；尚未提交时 latestScore=null，不可用 NA 代替未评分。`NA` 不进入该维度有效分母，但须报告数量与原因。

不可回答题明确说明当前资料不足、且没有补造具体答案，可判 correctness=CORRECT（分析值 2）。编造数字、身份或未来事实为 INCORRECT（分析值 0）。可回答题空答、工具失败或预算耗尽无法给答案，不能计为正确；运行失败独立记入系统错误率。引用格式合格仅说明来源 ID 有效，不能自动转换为引用支持或答案正确。

评分依据必须指出参考段落/结论，记录评分者身份、时间、规则版本、回答摘要哈希及源回答版本。评分修改追加审计记录，不覆盖旧值。若两次评审分歧，保存双方原评分，由有权限的真人裁决并解释；不得由 Agent 伪装真人裁决。

## 统计与约束

项目当前接口提供评分覆盖、双评数、争议数和全维度完全一致率；分维度质量分布与 kappa 需基于导出的真实评分另行计算，尚未评审时不宣称已有这些结果。分别报告各维度分布、已评分/未评分/不适用数量，按配置、可回答性和题型分层。质量指标分母为预登记的全部目标样本，另报告已评分样本的条件结果；未评分不得填零或填正确。系统失败计入端到端错误率，不得通过仅统计有答案样本制造提升。

复核样本报告原始一致率；有足够类别变化时报告 Cohen's kappa，二级有序评分可报告加权 kappa并公开权重。样本少或某类全相同时解释不稳定/不可计算，不能返回伪造的 1。配对比较以同题为统计单位，报告配对差异和区间；小样本不足以证明非劣化时明确不确定。

模型或 Agent 可给辅助建议，但必须 source=AUTOMATED/ASSISTED，与 HUMAN 分列；未由真人确认的建议不能进入人工指标。当前 HUMAN 评分 API 不接受 source/kind 字段；不得把辅助评分导入该接口冒充真人。参考答案也是审查材料，有错时需保留数据更正记录并重新冻结受影响数据版本，不可悄悄改标签使结果变好。

## 证据与复现

每个证据包含文档名、文件 SHA256、页码 1、段落序号、完整 Markdown 中的 UTF-16 `[startOffset,endOffset)` 位置、原文及 groupId。每个不同 groupId 是一个必需证据组，组内任一标签为可替代证据；不能要求替代标签全部命中。只依赖源位置，不依赖 chunk ID。

执行 `node scripts/generate-phase3-quality.mjs` 重现同版本字节；执行 `node --test scripts/generate-phase3-quality.test.mjs` 校验数量、标签、哈希、划分和拒绝损坏数据。生成器不含模型调用、时间戳或评分。`manifest.json`、`manifest.sha256` 固定分发文件；`near-duplicate-audit.json` 为跨划分字三元组 Jaccard≥0.65 的词面筛查，不宣称证明语义零泄漏。

预注册抽样补充：每个开发/验证划分固定4道不可回答和16道可回答，共8道不可回答；可回答题按topic/category轮转。冒烟预先选择首个可回答与不可回答各1道，之后复用其结果，不根据输出换题。

并发审计补充：评分、裁决、撤销和批量导入按知识库/评审项顺序串行锁定；裁决payload的reviewedScoreIds由服务端记录当时最新的有效双人评分版本。分析只采用晚于所有最新评分的裁决，之后发生的真人修订会重新产生待复核状态。账号存在与自动测试评分均不能证明真人身份。
