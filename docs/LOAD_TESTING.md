# 双 worker 与混合负载复现

本阶段使用两个实际 Java 21 进程、真实 PostgreSQL/pgvector，以及明确标记的本机可控模型适配器。**不代表 DeepSeek 吞吐、线上容量或可用性承诺。** 真实模型延迟/用量单独保存在质量和成本实验目录。

## 登记与执行

`scripts/quality-operations-harness.mjs` 在提交任何负载前保存机器 CPU/内存/系统、源码摘要、Git 状态、Java 版本、数据库实例和资源配置。两个 JVM 各 `-Xmx384m`、`ActiveProcessorCount=2`、worker 并发 1、数据库连接池上限 6；租约 6 秒、心跳 1 秒。端口 25435/28083/28084/39555 必须空闲，遇占用拒绝启动，不停止未知进程。

```powershell
$env:JAVA_HOME='F:\CiteBase\.tools\jdk-21.0.12.1+1' # 或本机 Java 21
& .tools/apache-maven-3.9.9/bin/mvn.cmd -f backend/pom.xml test-compile dependency:build-classpath '-Dmdep.outputFile=F:\CiteBase\.tools\phase4-process-classpath.txt'
node scripts/quality-operations-harness.mjs --record-build
node scripts/quality-operations-harness.mjs --run
```

在其他工作目录替换上述绝对路径。首次需下载依赖与 PG 镜像。编译后若源文件变动，重新编译并登记，不复用旧 class 文件。脚本只对自己创建的容器和进程注入故障；结束停止 JVM/故障门，保留专用数据库及原始报告。重复运行前先核对旧专用测试容器身份，停止它释放端口，不能删除已有业务数据。

## 故障矩阵

覆盖：有效租约不被另一实例启动抢走、双实例真实领取、kill 后评测检查点保留、租约过期后晚到写入拒绝、在途取消、数据库暂停 8 秒后恢复、实际 HTTP 429/504 的有限重试、客户端 2 秒超时与门控 5 秒晚到成功、Agent 崩溃的 UNSAFE_TO_RESUME、Agent 取消、在途文档删除和引用/缓存撤回。

客户端超时仅在测试适配器专用标记上启用，其余请求保持原等待行为以验证晚到。UNKNOWN 是结果未知，不能伪装为调用没有发生。删除场景验证产品已有的删除撤回，不冒称实现了团队共享 ACL 撤权。

## 负载口径

预登记闭环并发 1/2/4/8；每档预热 10 秒、测量最多 60 秒或 240 个操作。按固定十操作循环：索引 1、基础问答 4、Agent 2、评测 3。索引使用独立写入知识库，问答使用稳定读知识库，避免用主动变更语料制造不公平错误。可控供应商每阶段操作延迟 100ms，不是测得的真实供应商延迟。

异步请求等待终态后才计完成，202 不计成功。原始 `load-samples.jsonl` 保留所有失败、任务ID、提交和完成时间；`resource-samples.jsonl` 每 5 秒保存两 JVM 资源、数据库连接和 SELF 监控。耗时含排队和终态轮询；吞吐分母为最早提交到最晚完成，包含排空时间。达到操作上限会明确标记实际时长，不冒称持续满 60 秒。分任务类型分别统计，避免混合样本掩盖问题。

闭环结果不等于开放环固定到达率容量，存在协调遗漏限制。监控窗口可能包含此前故障任务，不能把该窗口累计失败率当作负载阶段失败率。当前机器同时运行其他本地服务，报告只支持此次资源约束和共存环境下的观察，不能外推生产 SLO。

## 结果真实性

报告在 `docs/results/quality-phase3/operations/two-process-*/report.json`。每项检查记录证据；FAILED/RUNNING 必须保留。脚本完成只说明故障断言和采样完成，不能单凭 PASSED 宣称某个延迟或错误率 SLO。最终报告应同时列出实际失败率、各档吞吐/P50/P95、资源、排队与恢复耗时。

首次执行在 Agent 崩溃断言处停止：脚本错期待 INTERRUPTED，而实际产品恢复契约是 FAILED/UNSAFE_TO_RESUME，返回空答案及 UNKNOWN generation。保留第一次报告；后续脚本严格验证实际契约和无重放，不把失败放宽成任意状态。
